# Retrospectivas por sprint

Formato: qué funcionó, qué mejorar y acciones para el siguiente sprint. Se completa al cierre de cada sprint,
con ambos integrantes, y se respalda con una captura del tablero (GitHub Projects) en `docs/gestion/capturas/`.

## Sprint 1 — Caso y requerimientos (Hito 1)
- **Objetivo:** caso validado, ERS v1, backlog inicial, casos de uso y metodología.
- **Qué funcionó:** definimos bien el caso de Aceros We-Corp y qué tenía que hacer el sistema. Dejamos escritos los requerimientos y el backlog desde temprano. Separar el proyecto en catálogo y ventas ayudó a ordenarnos.
- **Qué mejorar:** los requerimientos se podían haber revisado antes de cerrarlos. Faltó anotar mejor las tareas en el tablero a medida que avanzábamos.
- **Acciones para el Sprint 2:** revisar entre los dos los documentos antes de entregarlos y mantener el tablero al día.

## Sprint 2 — Diseño (Hito 2)
- **Objetivo:** diagramas de clases, ER, arquitectura, secuencia, despliegue y estados; contratos OpenAPI.
- **Qué funcionó:** los diagramas quedaron claros y explican bien cómo funciona el sistema. Dejamos definidas las APIs y las decisiones importantes, así no se pierde el porqué de cada cosa. La tabla de trazabilidad une los requerimientos con el diseño.
- **Qué mejorar:** algunos detalles quedaron incompletos. Falta el error 409 en el contrato de ventas y una nota del diagrama de base de datos puede confundir. El README cuenta una estructura que todavía no está en el proyecto.
- **Acciones para el Sprint 3:** corregir esos detalles del diseño, pasar el código a la nueva estructura y probarlo, y que los dos revisemos los cambios del otro antes de aceptarlos.
